# `Sessions\` — one directory is one session

The directory is simultaneously the name, the handle and the lock, so everything here is a claim about **whose** directory it is. The rules below hold for every file; each says what enforces it, and the gaps are named as gaps.

- **A path is canonicalised once, by `SessionPath`, and every derived name comes from it** — the mutex, `lock.json`, the index key. `SessionPathTests` covers the canonicalisation. **Nothing stops a new caller canonicalising a path of its own**, and two components that canonicalise separately eventually disagree about one path — at which point two processes hold the same session.
- **A path is refused at the door before it is canonicalised into anything, and the order inside that refusal is load-bearing.** `SessionDirectoryGuard` runs at `browserai_init` and `browserai_resume` only: the network question first, from characters and then `GetDriveTypeW`, with **no filesystem call in it**; the alias question second, because it opens a directory. `SessionDirectoryGuardTests` covers both, against real aliases this machine builds. **Nothing stops a new caller adding a filesystem call in front of the network check** — and it would not fail anything: the refusal would still be correct, twenty-two seconds later, inside the per-directory gate where every peer waits. The one thing that would catch it is a clock, and [a clock cannot be honest here](../../../TESTING.md#every-duration-is-a-hang-detector-or-it-is-a-defect).
- **Compare two Windows paths by upper-casing both sides and then comparing ordinally**, or ask for `OrdinalIgnoreCase`. `SessionPath.Key` and `SessionManager.Beneath` do, and so does every path comparison in `src\` — checked, not assumed. **`SessionDirectoryGuardTests` now asserts it**, and that is a correction: *previously "**Nothing asserts it**", written 2026-08-17*, and between then and 2026-08-19 the same defect arrived twice more with the network/alias guard. **It reproduced this time.** `dotnet test` at `cc45900`: **482 passed / 2 failed from Git Bash, 484 passed / 0 from PowerShell**, same tree, same commit — because the working directory arrives as `c:\…` from one shell and `C:\…` from the other, while `GetFinalPathNameByHandleW`, `QueryFullProcessImageNameW`, `GetShortPathNameW` and `QueryDosDeviceW` all answer upper-case whatever started the process. The two assertions repaired at `b4c970a` rested on the mechanism and on a report; these rest on a red run.
  - **The mechanism is `DriveLetterCase`**, and six tests in `SessionDirectoryGuardTests` are parameterised over it, so every path they compose is spelled both ways on every run. The `Lower` arm composes a spelling **no Windows API ever returns**, so a comparison that is not case-insensitive is red on every machine and in every shell. Proof it works without choosing a shell: the planted arm failed *from PowerShell*, with the identical two failures Git Bash had produced.
  - ⚠️ **CI is `pwsh` end to end (`build.yml`), so CI cannot see the shell-dependent form of this at all** — which is why it was reported twice from a machine and never once from a build. The `Lower` arm is what puts it in front of CI.
  - **Eleven sites carried the shape and all eleven were test assertions; `src\` had none.** Eight in `SessionDirectoryGuardTests`, one each in `HeadlessBinaryTests`, `StraySweepTests` and `SessionPathTests`. The one deliberate ordinal path comparison in the product is `ArtifactRouting.PrefixOf`, which separates names the product generated from names a caller chose — a genuinely case-sensitive question.
- **A holder is `(pid, creationFileTime)`, never a bare pid.** `LockRecordTests` and `SessionLockTests` cover the record and the reclaim path. **Nothing stops new code reading `ProcessId` on its own** — and a pid alone reclaims a live session's directory the moment Windows reuses the number.
- **Attribution may fail; detection may not.** `StraySweep` ends only what it can tie to both an image path BrowserAI owns and a window title it can read. Anything it cannot attribute is **reported loudly by full path and left running** — never terminated on a guess, never silently dropped. `StraySweepTests` holds the shape of this; the judgement about a new candidate kind is yours.
- **`lock.json` is append-only: every field is an ordered list of timestamped statements, and nothing is ever overwritten.** `LockRecord.Append` is the only way a field gains one, it appends only when the value changes, and it trims out of the **middle** so the first statement — the one `Created` is read from — survives. `LockRecordTests` covers the dedupe, the cap and the trim. **The rule this exists to serve is the one nothing can enforce: a session says how it got here, so BrowserAI never has to ask a caller to confirm what it already knows.** That is what deleted `acknowledgeCopy`, and the product now has zero confirmation flags — `ModelSurfaceTests.NoAuthoredToolAsksTheCallerToConfirmAnything` counts them, and cannot tell you that a new refusal *should* have been a returned fact.
- **A sharing violation on `lock.json` may be read as *owned*; nothing else may be read as *free*.** `SessionLock.ProbeForHolder` refuses in front of the per-directory gate on that one answer and falls through to the gate on every other — absent, mid-rename, denied, unparseable, or an open that succeeded. `SessionLockTests.AProbeThatFindsTheDirectoryFreeStillProvesItAtTheGate` fails if the free path ever skips the gate. **Nothing stops a new caller adding a second pre-gate shortcut**, and the one that would be added is the tempting one: with the gate skipped on the free path both contenders probe free, the rename retry loop becomes the serialiser, and the loser takes the name off a live holder's still-open handle.
- **A refusal is a sentence the model reading it can act on, and it lives in `SessionErrors`.** `ErrorCatalogueTests` proves every catalogue entry is reachable from a real path. **It cannot tell you that a refusal you wrote inline belongs in the catalogue**, which is the only way this rule is ever broken.
