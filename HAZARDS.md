# Hazard index

Every failure mode surfaced during research, in one checkable list. The overwhelming majority are **silent** — that is why they are enumerated rather than left to prose.

> **A hazard does not stop existing because the code that handles it was
> written.** This list is maintained by addition: rows gain a `Status` and the
> evidence that closed them, and are never deleted. It is what a review of the
> finished product is checked against.

**This table is a lens, not a record.** Each row states the hazard in one line and points at the place that establishes it: an article under [`kb/`](kb/README.md) where a measurement stands behind it, or the [README](README.md) where a decision does. Reading a row is not reading the evidence. A row whose *Established in* cell opens with `—` has no article to go to — it is a design consequence or a reading of the spec, recorded here only.

**This file is deliberately self-contained**, so that nothing it depends on can be reorganised out from under it. It once carried 146 links into a set of design documents that were always going to be consumed and deleted — on 109 lines, 107 of them table rows — including its own shorthand legend, the one line that gave every `§X` token below it its meaning. Every one of those links is now the text it was linking with, the legend defines the shorthands in words, and the links that remain point only at things with no scheduled end: [`kb/`](kb/README.md), [`README.md`](README.md), [`ARCHITECTURE.md`](ARCHITECTURE.md) and the code. **A row's evidence names files and test methods rather than document anchors** for the same reason.

**If you find a new hazard, add it here** — and put the fact behind it in the `kb/` article that owns the topic. This list is what a reviewer checks the implementation against.

**It is maintained by addition, and it has been wrong by omission.** On 2026-08-15 eight silent-failure hazards established elsewhere in this document — the UNC-title stall, silent walk truncation, the forgeable window signal, strangers' paths from enumeration, races R3 and R5, Firefox's blocking modal, and disk exhaustion mid-provision — were absent from it. A gap here is a defect in the list, never evidence that the hazard is not real.

## The four columns, and what each is for

**Restructured 2026-08-16**, because a list that could only ever grow was answering half the question. It said what could go wrong and had no way to say *this one cannot happen any more, and here is why* — so a hazard that had genuinely been closed sat beside one nobody had touched, indistinguishable.

| Column | What it holds | The rule |
|---|---|---|
| **Why it happens** | The mechanism underneath the symptom, where it is knowable | **Never guessed.** `—` means the cause is not established, and an honest gap is worth more than a plausible story. This is the column that stops the same *class* recurring somewhere new: a fix aimed at a symptom closes one row, a fix aimed at a cause closes the ones nobody has written yet |
| **Established in** | Where the hazard is shown to be real | Unchanged |
| **Status** | `open` or `closed`, with the date it closed | Default `open`. A row is never deleted, so `closed` is the only way a hazard leaves the working set |
| **How we proved it** | The evidence that closed it | **A row marked `closed` with `—` here is not closed.** That is the whole point of splitting the two columns: `closed` is a claim, and this column is what makes it checkable |

**What `closed` may rest on, in order of strength.** A **measurement** that shows the failure cannot occur; a **test** that goes red if it starts occurring again; a **decision** that removes the possibility, such as not shipping the component the hazard lives in. Only the second of those keeps working without anyone watching, so a row closed by measurement or by decision names what would re-open it.
