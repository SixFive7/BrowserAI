## (2) Product code that deletes under a browsers folder (f68ae4cf)
- **BrowserProvisioner deletes two kinds of things.** Neither is `__dirlock` or `.links`:
  - It deletes the revision directory (`chromium-<rev>`) on reinstall (lines 1089 and 1184), on an abandoned tree with no marker (1567), when a cap fires (1758), and when the installer exits nonzero or leaves no marker (1771).
  - It empties `.downloads\<family>` (2259), and only in the process that holds that family's mutex, right before it starts its own installer. A second process for the same family only watches for the marker.
- **RevisionPrune (252)** deletes old revision directories after a successful install. It only touches names that start with a browser prefix, so it skips `__dirlock`, `.links` and `.downloads`.
- **Everything else** deletes outside the browsers folder: instance directories, sessions, live markers, the index, lock files and logs. `DataRootDisposal` removes the whole data root, but only from the uninstall hook when the person asks for it. arch2-ps installed nothing.
- **A coordinator starting in a root mid-install** runs the stray sweep, which ends processes and deletes no files, and the live-marker reclaim, which only touches `<root>\live\`. Neither meets any of the conditions above.
