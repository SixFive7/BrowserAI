## Does my recommendation change?

Partly. The repro shows the installer behaved exactly as its source says, so this is not an upstream defect. But the log check makes the reclaim a less certain cause of this particular deletion. Revised:
1. **Record the whole installer error.** This now matters more. Also make the reclaim log every directory it deletes, with the UTC time and its pid, so the next deletion names its deleter.
2. **Keep the reclaim away from live directories** with an owner or liveness check. The orphaned install is a measured case of it deleting a live directory, even though it is not proven to be this one. Your "every host takes the suite lock" rule covers it for now; this would make it a mechanism.
3. **New: look into the second process in the victim's app root** (pid 91780). The logs cannot rule it out.

The retry, serialized-install and upstream options are unchanged.

HAZARDS row: the branch and the error are now measured (ENOENT, because the lock was deleted). Moving the row from "upstream's half" to "deleted by another process", with the deleter still open, is for the maintainer to decide.
