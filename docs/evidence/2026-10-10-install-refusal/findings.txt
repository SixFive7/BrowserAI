1. THE ANSWER

- A hook that exits non-zero does not stop a Velopack install. Measured twice, silent. Setup
  logged "[WARN] Hook exited with non-zero exit code: 5", then "Writing uninstall registry
  key..." and "Installation completed successfully!", and exited 0. Everything stayed: 209
  files (203,836,749 bytes), Update.exe, the Start Menu shortcut and the Add/Remove entry.
  Nothing is rolled back.
- In a silent install the caller cannot see the refusal. Setup exits 0 either way. The only
  trace in Setup's own output is that WARN line.
- The install hook can see everything a refusal needs. Measured from inside the hook: the
  install root (InstallLocation.RootAppDir is the --installto folder); the pack id
  (BrowserAI.app.test); the installer's data root (BROWSERAI_ROOT, which InstallerSettings.Read
  also returns); whether the install is silent (the hook's parent is the installer, its command
  line carries --silent --log ... --installto ..., and
  DataRootDisposal.IsSilent(ProcessLiveness.ParentCommandLine()) returned true).
- A refused install at a non-standard folder still rewrites the pack id's Add/Remove entry and
  the title's Start Menu shortcut. Measured: the second refused install moved both from root-1
  to root-2. For the shipping pack these are the standard install's
  HKCU\...\Uninstall\BrowserAI.app and BrowserAI.lnk. Uninstalling the refused folder
  afterwards deletes that entry.
- Non-silent (read in the source, not run): a person sees Velopack's warning, "BrowserAI Setup"
  / "Install Partially Succeeded" / "Installation has completed, but some steps may have
  failed. ...", with one OK button. After OK, Velopack writes the entry and starts the refused
  folder's current\BrowserAI.exe with VELOPACK_FIRSTRUN=true.

2. SOURCE READINGS AT 1.2.161

2.1 Where the hook runs, and what follows a failure. src/bins/src/commands/install.rs:189-258
(install_impl) does these steps in this order: extract Update.exe and the stub (205-213); copy
the package (215-218); extract current\ (220-222); apply a channel override (224-230); refuse a
missing main exe (232-237); create the shortcuts (239-242); run the install hook with a 30 s
timeout (244-245), and on failure call dialogs::show_install_hook_warning (246) and carry on;
write the uninstall entry (250); only when not silent, log "Starting app..." and start the app
with VELOPACK_FIRSTRUN (252-255). There is no rollback for a failed hook: install() (147-165)
rolls back only when install_impl returns Err, and only by restoring a root it had renamed
aside for an overwrite (156-164); a failed hook does not return Err, so the install logs
"Installation completed successfully!" (151); src/bins/src/setup.rs:60 exits 0 whenever
real_main returns Ok.

2.2 run_hook (src/bins/src/windows/util.rs:19-62). The hook is <root>\current\BrowserAI.exe

logged at ERROR (54-56). force_stop_package(&root_dir) runs after every one of those outcomes

it. process_win.rs:352-412 (run_process): the flags are CREATE_NO_WINDOW |
CREATE_UNICODE_ENVIRONMENT (388-392), and Setup logged PROCESS_CREATION_FLAGS(134218752), which
is 0x08000400; the environment is a copy of Setup's whole environment (make_envp, 135-156),
which is how BROWSERAI_ROOT reaches the hook; CreateProcessW is called with

4. WHAT "TWO INSTALLS OF ONE APP ID" MEANS FOR A REFUSED INSTALL

The kb section (kb/packaging/velopack.md, measured 2026-09-14, re-established 2026-09-24 at
1.2.158) says the entry is named by the id, not by the location; a second --installto install
rewrites InstallLocation, DisplayIcon, UninstallString and QuietUninstallString; and the first
uninstall of either root deletes the entry while the other root is still complete. This run
re-establishes all of that at 1.2.161, with the second install refused by its hook, and shows
what a refusal cannot prevent: the entry is written after the hook (install.rs:250) and the
shortcut before it (239-242), so a refusal in the hook changes neither, and install 2 moved both
although its hook exited 5. For the shipping pack, an --installto install on a machine that
already has a standard install leaves the standard install's HKCU\...\Uninstall\BrowserAI.app
naming the refused folder; %APPDATA%\...\Programs\BrowserAI.lnk (the shipping title is
BrowserAI, so it is the same file) starting the refused folder's current\BrowserAI.exe; and
about 204 MB of files in the refused folder. Settings then offers to uninstall the refused
folder, because that is what the entry names, and doing so deletes the entry unconditionally
(registry.rs:65; measured: uninstall 1 deleted an entry that named root-2) and removes
BrowserAI.lnk, because it now points into the refused folder (measured: uninstall 2 removed the
shortcut into its own root). The standard install then still has its files and its Update.exe,
but Windows no longer lists it. A refusal in the hook does prevent BrowserAI's own writes:
measured, none happened (no client registration, the sandboxes stayed empty; no scheduled task;
no PATH entry; no CLSID activator; no background-task.xml).

5. READINGS IN BROWSERAI AT db50964e THAT BEAR ON THE DESIGN (NOT MEASURED)

The installer's first-run start after a refused non-silent install: src/BrowserAI/Program.cs:172-185
reads VELOPACK_FIRSTRUN, serves no hook, and calls App.Program.Run; src/BrowserAI.App/Program.cs:160-164
takes the data root from --data-root, or from the saved background-task.xml (SignInTask.cs:98,
328-334), or uses the default, and opens its process log there; a refused install saved
nothing, so that log lands in the default %LOCALAPPDATA%\BrowserAI; PersonStart.Show
(Program.cs:251-269) finds no background, finds the task unregistered (PersonStart.cs:179),
finds no saved definition (183-189, PersonStartLog.NoDefinition) and returns NotShown, and the
app then exits 1 with no window. So after OK the person sees nothing more, unless that start is
taught to explain; it is the only place BrowserAI's code runs with a window allowed during a
non-silent install.

The real uninstall hook on a refused install's leftovers: HookRegistration.cs:141, 154 take the
data root from InstallerSettings.Read (InstallerSettings.cs:90-99): the uninstaller's
BROWSERAI_ROOT, else the saved definition, else the default. An uninstall started from Settings
has no BROWSERAI_ROOT, and a refused install saved no definition, so the hook would act on the
standard install's data root: it writes its registration record there (292), and in a
non-silent uninstall it asks whether to delete that root (335; DataRootDisposal.cs:188). Three
things have their own guards, by reading: the background it asks to stop is named after the
refused root (273); the PATH step touches only its own folder (304); removing the toast
activator checks who owns it (ToastActivatorStep.cs:47, ToastActivation.cs:140-151). What
RegisterAI's unregister does with a client entry that names the standard install was not read.

Hook budget: the install hook gets 30 s (install.rs:245); anything left running under the root is
killed afterwards (util.rs:60); a process whose image is outside the root survives
(util_windows.rs:35-102).

6. WHAT COULD NOT BE ESTABLISHED

- No non-silent install was run, because it would show windows; 2.4 and 2.5 are readings, and
  the dialog language is inferred, not seen on screen.
- The install hook itself never showed up in the process poll: hooks take about 70 ms by
  Velopack's own count, against a poll every 0.5 s. "Nothing ran from the root after exit"
  rests on the 15 s post-exit polls (the same poller did see Update.exe) and on Velopack's scan
  ("0 matched").
- The true branch of the standard-root comparison was never observed: an install without
  --installto would have gone into %LOCALAPPDATA%\BrowserAI.app.test, outside the brief. Both
  records show the two paths, so the comparison can be checked by eye.
- A throwing callback and an exit-0 install hook were not run; both are readings, and the exit-0
  path was seen only in the patched uninstall hooks.
- Velopack's real 3 s removal delay was not observed (a rig artifact, 3.4).
- Section 5 is reading only; the patched uninstall hook did nothing.
- The 211 against 205 file count was not examined.
