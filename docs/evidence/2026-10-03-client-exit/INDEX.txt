client-exit -- what a client does to a stdio MCP server when the session ends (Q356 a), 2026-10-03, all times UTC.
Everything here is scratch (gitignored). Nothing under docs\ was written.

RIG
  rig\ExitRig\*.cs        one .NET 10 console app, several modes:
                            server     the dummy MCP server (tool "ping"); logs QPC + precise UTC; creates an unnamed,
                                       non-inheritable KILL_ON_JOB_CLOSE job and starts a stand-in in it (CREATE_SUSPENDED,
                                       AssignProcessToJobObject, ResumeThread, CREATE_NO_WINDOW); on stdin EOF waits
                                       --delay-ms, closes the job, exits 77. --call-delay-ms delays tools/call answers.
                                       --keeper child|orphan starts a keeper OUTSIDE its job (option-c probe).
                            standin    sits in the server's job and logs.
                            keeper / launcher   the option-c probe (keeper watches the server by handle, then needs 5 s, exits 88).
                            run/batch  the harness: launches the client (CreateNoWindow, pipes) or runs it in a ConPTY
                                       (Pty.cs), observes the tree by parent pid with a ~1 ms toolhelp poll, opens a handle on
                                       every descendant at once and records exit time (kernel FILETIME and QPC) and exit code.
                            fakeclient the controls (runs\controls): close / taskkill / taskkill-then-close / terminate / exit-self.
                            ttyprobe   proved that a ConPTY child picks up the harness's redirected handles unless
                                       STARTF_USESTDHANDLES is set with NULL handles (runs\ttyprobe).
  rig\vscodehost.js       node stand-in for the extension host's transport (sdk-close / host-exit), as read in extension.js.
  stub\anthropic-stub.js  stateless Messages API stub (tool_use until a tool_result exists, then "stub-turn-finished").
  stub\openai-stub.js     stateless Responses API stub (function_call to mcp__probe/ping, then "done").
  tools\gen*.ps1          batch generators (gen = cc/cx, gen2 = cc2/extra, gen3 = vsc, gen4 = keeper, gen5 = cxnew, gen-tui = tui).
  tools\analyze.py        one TSV row per server instance per run; tools\summarize.py groups them; tools\ranges.py timings.
