== WHAT THIS SETTLES ==
1. THE BEHAVIOUR IS TRUE AND IS SILENT. Step B is the exact shape RELEASING.md describes --
   a lock file present, --locked-mode, no --force-evaluate, and a newer version available.
   It exited 0 with "0 Warning(s) 0 Error(s)", left the lock at resolved=1.0.0 and the assets
   at BrowserAi.Probe/1.0.0, and said nothing about the 1.1.0 sitting on the feed. The float
   was not re-evaluated and nothing reported that it was not.
2. THE CITATION IS WRONG. NU1512 does not describe this case. Per Microsoft Learn
   (https://learn.microsoft.com/nuget/reference/errors-and-warnings/nu1512, fetched 2026-09-23)
   it reads "RestoreForceEvaluate overrides RestoreLockedMode; the packages lock file will be
   re-evaluated and regenerated, and locked mode is ignored", and it fires only when BOTH
   properties are set -- the opposite arrangement, and the one a one-step locked build does not
   have. The Learn page's own Note gives the default: "This warning is raised by default
   starting with the .NET 11 SDK (SdkAnalysisLevel value 11.0.100 or higher)."
   POSITIVE CONTROL that the warning is reachable and is not just absent from this SDK: step D
   (both flags, SDK default SdkAnalysisLevel) was silent, and step D2 (the same command with
   -p:SdkAnalysisLevel=11.0.100) produced
     C:\Program Files\dotnet\sdk\10.0.401\NuGet.targets(198,5): warning NU1512: RestoreForceEvaluate
     overrides RestoreLockedMode; ... 1 Warning(s).
   So the scan can find it; it simply does not fire in the case the document cites it for.
3. WHAT LOCKED MODE IS LOUD ABOUT is a lock that disagrees with the graph, and that is a
   different failure with a different code. Step E:
     error NU1004: The package reference BrowserAi.Probe version has changed from [*, ) to
     [1.1.0, ).The packages lock file is inconsistent with the project dependencies so restore
     can't be run in locked mode. Disable the RestoreLockedMode MSBuild property or pass an
     explicit --force-evaluate option to run restore to update the lock file.
     exit=1, 1 Error(s).
   That is precisely why the float going dead is silent: a float that is never re-evaluated
   produces no disagreement for locked mode to be loud about.
