What changed in BrowserAI 1.2.0

Released 2026-10-20.

Added

✨ A Start Menu click opens BrowserAI's page in your own browser.

The page replaces the configuration window. It lives at an address on your own machine that BrowserAI makes for each run.

✨ A downloaded update that has to wait says so in a toast that counts down to its install.

The toast names what holds the update and has two buttons, Install now and Wait for inactivity.

✨ browserai_close closes a session's browser and keeps the session.

A later browserai_resume opens it again with its logins, cookies and tabs.

✨ A broken install is told to the person, in a toast and on every page of the dashboard.

Every session is refused until BrowserAI is reinstalled, and the page says how.

✨ The dashboard and the toast name each conversation the way its client shows it.

A VS Code window's tabs are listed together under the window.

Changed

💥 BrowserAI is one program, BrowserAI.exe, and a client starts it with --mcp.

An update rewrites the registrations that name the old file.

💥 One BrowserAI runs in the background from sign-in, and a client's start hands its calls to it.

The background holds every session and ends at sign-out, at an uninstall or for an update.

🔧 The tool descriptions, the answers, the pages and the log say the same things in fewer words.

The tool list a model is handed is about 2,200 characters shorter on every prompt.

Fixed

🐛 A Firefox started while Shift is held no longer stalls in safe mode.

Every Firefox BrowserAI starts has its safe mode key switched off.

🐛 Playwright's own registry of browsers no longer grows without end.

BrowserAI asks Playwright to tidy it at every session close.
